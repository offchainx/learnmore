### 2.3 产品闭环与价值方向

**用户已确认：** Learn 阅读/交互微课 → Practice 智能推荐练习 → Ask AI 助教解答 → Analyse 分析学习情况 → 把积累用于下一轮学习和练习。

**2026-09-23 的重点修正：** 核心不是单独告诉学生“下次练什么”，而是让学习和练习层层建立在已有基础上，像向上走，每一步都承接前一步。系统结合进度、薄弱项与学习过程安排体验；Analyse 要让学生和家长看见价值。

这是一条产品方向，不等于所有关联能力已被验证。具体推荐依据、报告权限、跨 tab 记录、学习状态指标仍由 Codex 核验。用户提到的“专注力”暂记录为希望理解的学习状态，不直接宣称能测量心理专注力；学习时长/点击/答题节奏只能在验证后说明其实际含义。

## 3. 正在打磨的重点

### 3.1 「积累」：每一步，都站在上一步的基础上

**建议核心表达（待定稿）：**

> 每一步，都站在上一步的基础上。
>
> 今天弄懂的，成为下一次解题的底气；今天卡住的，成为下一次练习的重点。你的学习，一步步接起来。

备选短句：「把每一次努力，变成往上走的一步。」／「学过的每一点，都在托起下一步。」

**故事逻辑：** 学一点 → 用题目检验 → 卡点得到解释 → 再练提供新证据 → 看见进步与未稳之处 → 接着往上学。Ask 随时提供帮助，不要求每次机械地经过四个 tab。

**画面建议：** 用同一个学生、同一个知识点的学习轨迹逐层向上展开；每一层显示具体变化，而不是积分增长或抽象上升箭头。标题可保留温暖感，靠实际演示解释“向上”。

**避免误导：** “传统方式像平地走”是创意比喻，不作为传统学习无效的事实断言；学习有遗忘和起伏，不画成每次使用都必然提升的保证。未验证的推荐/分析能力不靠含蓄文案绕过事实核验。

### 3.2 Analyse 要把什么价值呈现出来

| 学生/家长会问什么 | 建议呈现的证据 | 不足以单独证明价值的东西 |
| --- | --- | --- |
| 我现在能做什么了？ | 同一知识点前后独立作答、错误类型的变化 | 只显示看过几节课 |
| 哪些地方还不稳？ | 持续出错的知识点及对应记录 | 无依据的精准能力百分比 |
| 这两周的努力有什么结果？ | 已学内容、复习轨迹、掌握证据与剩余卡点 | 只显示时长、XP 或连胜 |
| 接下来值得把时间放在哪里？ | 根据已验证规则产生的学习/练习建议 | 没有解释来源的“智能推荐” |

**定位建议：** Analyse 是让努力看得见、说得清的总结；它不只是再一个漂亮图表页。优先使用真实 App 指标，不为了官网故事发明新指标；家长能否直接查看报告需另行核验。

### 3.3 三张同风格轮播的制作简报

| 页 | 已选主标题 | 支持文案草案 | 视觉场景建议 |
| --- | --- | --- | --- |
| 第一页 · 学生入门 | 把不会的，一点点学会。 | 从一个知识点开始，看懂、动手，再把卡住的地方弄明白。 | 自然日光下的学生书桌、阅读与交互微课；使用原图暖白/深蓝/蓝色按钮 |
| 第二页 · 积累 | 每次复习，都接着上次的进步。 | 今天学会的，托起明天的下一步。 | 同一视觉世界的学习记录逐层向上展开；承接原有基础，不做夸张成绩曲线 |
| 第三页 · 家长 | 孩子学了什么，更要看懂他卡在哪。 | 坐在书桌前很久，到底哪里还不会？让每一次学习，留下看得明白的线索。 | 家长与学生一起查看学习过程；不伪造家长后台或真实家庭推荐 |

建议统一 16:9 桌面海报比例（目标 2560×1440，记录工具实际输出尺寸），统一 Logo、字号层级、色调和 CTA 区域；手机版另行构图，不能简单缩小整张图。

实现时中文标题、按钮与轮播控制用网页文本/组件，照片与插画独立作素材，避免整张海报烧入文字导致手机不可读。三张图是同一方向的三个故事，不是再次选择三种网站风格。

轮播建议：可手动切换，支持手机滑动、页码和前后按钮；如自动播放，给予足够阅读时间并可暂停，用户操作后暂停；减少动态偏好下不自动播放。具体节奏在预览中验证，主要按钮始终可见。

**以下为内部设计用 mock，非真实用户评价；每条展示时都要保留这一标记。** 不搭配虚构实名、学校、头像、五星认证或成绩数据。正式发布前换成真实反馈，或改写成公开的使用场景。

### 3.5 报名流程：Google Forms 方案

**用户偏好：** Google Forms，便于 Victor 直接查看汇总。表单必须包含个人信息、学习情况与联系方式；学习情况用于筛选认真评测者，填表不等于入选。Google 官方支持将回复保存到关联的 Google Sheets：[说明](https://support.google.com/docs/answer/2917686?hl=en)。

**建议本期：** 官网 CTA → Google Form → Google Sheets 招募总表 → Victor 人工 WhatsApp 沟通 → 确认资格 → 安装与两周评测。报名不自动开通账户或免费权限，待实际运营流程确定。

Google Sheets 可以承担本期运营名单；如还需要写入产品数据库，要额外设计同步、重复报名处理和失败恢复，不能把“表单连 Sheets”说成已接通现有数据库。正式决定前保留当前站内报名功能，不创建两个同时使用且记录分散的入口。

**字段草案（待一起确认）：** 按“个人信息 / 学习情况 / 联系方式”三个组组织；学习情况建议问当前困难、希望改善的科目、能够投入的体验与反馈时间，不以成绩高低直接排除认真参与者。原字段草案： 申请身份（学生/家长）、如何称呼（昵称即可）、联系人的 WhatsApp 号码及国家码、学生年级、设备类型、想重点体验的科目/问题、是否愿意完成两周体验并反馈、同意就本次内测联系。用于 TestFlight/Android 邀请的邮箱是否报名时收集或沟通后收集待定。家长代报名填写家长联系方式，不默认收集孩子电话。

无需身份证、家庭经济情况或详细住址。真实表单与汇总表不公开回应名单/汇总；收集用途、访问权限、保留期限在启用前明确。以上是实际新增联系方式的设计要求，不涉及本轮数据收集。

成功文案建议：「已收到你的申请。我们会通过 WhatsApp 联系你了解体验安排，确认入选后再发送内测邀请。」不承诺尚未确定的联系时限。
