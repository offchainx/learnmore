# 练习中心章节层级与入口规则备忘录

> 用途：记录当前关于 `chapters.parent_id`、叶子章节/父章节、题目标记、练习入口隔离、知识蜂巢、考试预测、薄弱点快修的讨论结论。
> 状态：讨论备忘录，尚未单独升级为正式开发任务。

## 术语定义

### 父章节
- 指知识树中的非叶子节点。
- 用于表达更高一级的知识域，例如：
  - `语文基础知识`
  - `生命科学`
  - `中国古代史`
- 父章节主要用于：
  - 聚合统计
  - 内容管理树
  - 展示章节路径
  - 后续权限/导入/审核归类

### 叶子章节
- 指知识树中最终可直接挂题的章节节点。
- `questions.chapter_id` 应只指向叶子章节，不应直接挂到父章节。
- 叶子章节主要用于：
  - Chapter Drill
  - Smart Drill 弱点识别
  - 知识蜂巢节点
  - 薄弱点快修
  - 题目录入归档

### CMS
- `CMS` = `Content Management System`
- 在当前项目语境里，可以理解为“后台内容管理系统”。
- 典型能力包括：
  - 创建/编辑/删除章节
  - 调整章节层级与排序
  - 导入题目
  - 审核题目
  - 维护真题卷与标签

## 当前建议

### 1. `chapters.parent_id` 建议正式启用
- `parent_id` 应表达真实知识层级，而不是只为了页面视觉结构服务。
- 当前是比较好的启用窗口，因为题目和答题记录还在持续整理中。
- 若等大量题目、attempt、统计口径都固化后再补层级，迁移成本会更高。
- 正式结论：`parent_id` 建议作为正式知识树字段启用。

### 2. UI 展示和知识层级解耦
- `parent_id` 用于知识结构，不必强制等于页面展示结构。
- 练习中心的章节地图、知识蜂巢默认只消费叶子章节。
- 父章节用于：
  - 汇总统计
  - 后台管理
  - 路径展示
  - 上层知识域分析
- 正式结论：
  - 父章节用于归类、聚合、路径与管理
  - 叶子章节用于挂题、训练、掌握度与蜂巢节点
  - 页面默认消费叶子章节，聚合分析才读取父章节

### 3. 题目必须有最小权威标记
- `subjectId`
- `chapterId`（叶子章节）
- `difficulty`
- `isPastPaper`
- `paperId`
- `source`
- `tags`
- `status`

### 4. `chapterId` 与 `tags` 的关系
- 每道题必须有一个主 `chapterId`
- 该 `chapterId` 必须指向叶子章节
- 一道题可以有多个 `tags`
- `tags` 用于表达：
  - 跨章节知识点
  - 细粒度能力点
  - 检索、推荐、后续知识点分析
- `tags` 不替代 `chapterId`
- 当前建议的责任边界：
  - `chapterId` 负责主归属、章节训练、章节统计、蜂巢节点
  - `tags` 负责补充归类、跨知识点关联、后续推荐增强

### 5. 多知识点题目的处理
- 如果一道题涉及多个知识点或多个章节：
  - 必须选择一个主叶子章节作为 `chapterId`
  - 其他相关知识点通过 `tags` 记录
- 现阶段不建议只靠 `tags` 替代章节结构
- 原因：
  - 章节训练需要稳定主归属
  - 章节统计和知识蜂巢需要唯一主键
  - 自由标签如果没有主章节约束，后续会快速失控

## 正式规则固化

### 1. `parent_id` 是否正式启用
- 结论：正式启用
- 用途：
  - 表达真实知识树
  - 承载父章节与叶子章节关系
  - 支撑后续聚合统计与内容管理

### 2. 叶子/父章节消费规则
- 结论：正式区分
- 规则：
  - `questions.chapterId` 只挂叶子章节
  - Practice 默认展示和消费叶子章节
  - 父章节不直接作为常规练习入口
  - 父章节用于汇总、管理和路径展示

### 3. 真题与其他入口是否彻底隔离
- 结论：建议彻底隔离
- 规则：
  - `isPastPaper = true` 的题只进入 `Past Paper`
  - `isPastPaper = false` 的题才进入 `Smart Drill / Chapter Drill / Mock Arena`
  - `Past Paper` 与其他三个正式选题入口不共享题池

### 4. Error Wiper 的正式定义
- 结论：Error Wiper 不是独立题库入口，而是错题修复视图
- 规则：
  - 用户在正式练习入口答错后，错题通过 `user_attempts` 聚合进入 Error Wiper
  - Error Wiper 不应维护一套独立平行题库
  - 同一题重复答错应累计历史，而不是重复建题
  - 后续若要“退出错题重点池”，应由修复阈值决定，而不是手工孤立删除

## 练习入口规则

### 题目池分层
- `Smart Drill`：个性化训练池
- `Chapter Drill`：章节定向训练池
- `Mock Arena`：模拟卷生成池
- `Past Paper`：历年真题卷池
- `Error Wiper`：错题修复视图，不是独立题库池

### 历年真题隔离规则
- `isPastPaper = true`
  - 只进入 `Past Paper`
  - 不进入 `Smart Drill / Chapter Drill / Mock Arena`
- `isPastPaper = false`
  - 才允许进入 `Smart Drill / Chapter Drill / Mock Arena`

### 错题进入 Error Wiper
- 用户在任一正式练习入口答错后，错题应进入 `Error Wiper`
- `Error Wiper` 应基于历史 `user_attempts` 聚合，不应维护一套平行题库
- 同一题多次答错应累计历史，而不是重复建题
- 当前业务定义上，`Error Wiper` 属于“错题回收与修复模式”，不是首轮投题模式

## 统计口径建议

### 知识蜂巢
- 默认按叶子章节计算
- 建议设置最小样本数门槛，避免单题误判
- 掌握度应优先使用“近期权重更高”的加权正确率
- 父章节掌握度可由叶子章节向上聚合

### 薄弱点快修
- 应基于“近期正确率低 + 样本量足够 + 最近仍在出错”的叶子章节
- 输出时可展示父章节路径，但修复动作仍落在叶子章节

### 考试预测
- 不建议只看使用时长
- 建议至少综合：
  - 近 30 天有效答题正确率
  - 课程完成度
  - streak
  - 章节覆盖率
  - 真题表现（后续可增强）

## 实施注意点

### 若启用 `parent_id`
- 需明确哪些查询只读叶子章节
- 需避免父章节混入当前 Practice 叶子节点展示
- 需在 `Practice` 聚合中增加“是否叶子节点”的消费规则

### 若启用“真题不重叠”
- 需在 Smart Drill / Chapter Drill / Mock Arena 的选题查询里统一加过滤
- Past Paper 继续以 `isPastPaper = true` + `paperId` 为准

### 若采用 `chapterId + tags`
- 需固定 tags 命名规则，避免自由文本失控
- 推荐后续逐步把高频 tags 演进为正式知识点表，而不是长期停留在自由标签
