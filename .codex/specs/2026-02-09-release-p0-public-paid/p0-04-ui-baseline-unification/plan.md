- 执行原则：先文档、后开发；未获用户确认前禁止进入实现。

## 强制门禁（本任务必须满足）
1. 完成 spec.md、plan.md、tasks.md、acceptance.md 四件套并通过审阅。
2. 明确 Server Action 或接口契约：输入校验、输出结构、错误结构、幂等与并发策略。
3. 明确数据落表点：逐表列出关键字段与校验 SQL。
4. 验证环境固定为 本地 + 预发，两轮都要留下证据。

## 验证步骤（固定流程）
1. 本地：先跑成功路径，再跑失败与越权路径，记录 Action 输入输出与 SQL 前后快照。
2. 预发：复测同一批关键场景，验证幂等与并发行为，确认结果一致。
3. 回归：执行受影响页面最小冒烟，确认无阻断。

## 风险与回滚
- 触发回滚：核心路径阻断、数据写入异常、重复写入导致脏数据。
- 回滚步骤：回滚任务提交 -> 恢复旧入口或旧行为 -> 重新执行本地与预发冒烟。
- 观测要求：日志可定位 userId、action、result、timestamp。

## 开发启动条件
- 仅当用户在文档审阅后明确批准，才允许切换到开发实施阶段。

## 视觉定稿顺序

### T-004.2 练习中心总体视觉气质定义
- 目标：先锁定练习中心整条产品线的共用气质，避免每个模式单独长相。
- 已冻结方向：
  - 总体方向：专业训练舱
  - 材质：磨砂舱体
  - 强调策略：单主色 + 状态色
- 需要产出：
  - 背景层级规则
  - 面板厚重感与边框策略
  - 标题层级与统计信息密度
  - 图标和动效语气
  - 禁止项（避免 AI SaaS 模板感、避免 neon 游戏厅感）
- 冻结结论：
  - 主强调色：冷钴蓝（用于主 CTA、选中态、关键进度、焦点高亮）
  - 状态色：成功=翠绿、警告=琥珀、危险=赤红、锁定/禁用=冷灰
  - 背景层级：外层深墨黑 -> 页面壳深石板蓝 -> 面板深蓝灰 -> 浮层更亮一级
  - 面板材质：以磨砂实体面板为主，允许极轻微 blur，但不采用大面积玻璃态
  - 边框策略：细边框 + 低对比描边，优先用层级与明度区分，而不是大阴影
  - 圆角策略：主面板中大圆角，内部控件较小圆角，避免全站统一大圆丸子风格
  - 排版策略：保留 `Inter + Noto Sans SC`，标题偏紧凑、统计数字更醒目、说明文字降噪
  - 图标策略：统一线性图标，不使用卡通插画、吉祥物、表情化装饰
  - 动效策略：仅保留功能性转场与状态反馈；默认 160-220ms，禁止无意义 pulse 与漂浮
  - 数据密度：每屏允许高信息密度，但必须保持强分区与稳定对齐
  - 文案语气：偏训练、复盘、提分，不使用“AI 帮你”“超智能”“魔法式”表达
  - 禁止项：
    - 泛紫 AI SaaS 渐变作为主视觉
    - 大面积 glow / neon 边缘发光
    - 玻璃卡片堆满整页
    - 模式之间各自一套完全不同的视觉皮肤
    - 为了“酷”而牺牲做题可读性

### T-004.3 练习中心主页面方案
- 页面对象：`/dashboard/practice`
- 目标：从“模块堆叠页”重构成“训练指挥台”。
- 需要定义：
  - 首屏必须回答的三个问题：最弱哪里、今天该练什么、最快提分入口是什么
  - `PracticeSubjectBar` 的位置与交互
  - `PracticeModeGrid`、`ChapterProgressSection`、`PastPaperLibrarySection`、`PracticeCoachPanel` 的主次关系
  - 主 CTA 与次 CTA 的层级
- 冻结结论：
  - 页面定位：不是内容目录页，而是“单科训练控制台”
  - 首屏职责：
    - 问题 1：我当前最弱哪里
    - 问题 2：我今天最应该练什么
    - 问题 3：我最快能从哪里开始
  - 桌面端结构：
    - 顶部：页面标题区 + 当日训练摘要
    - 第二层：`PracticeSubjectBar`
    - 主体：`8/4` 双栏布局
    - 主栏（8）：`PracticeModeGrid` -> `ChapterProgressSection` -> `PastPaperLibrarySection`
    - 侧栏（4）：`PracticeCoachPanel`
  - 移动端结构：
    - 顶部摘要保留，但压缩成单卡
    - `PracticeSubjectBar` 横向滑动吸顶
    - 主栏内容改为单列任务流：推荐入口 -> 模式入口 -> 章节进度 -> 真题卷库 -> 教练板摘要
    - 教练板完整内容下沉到底部，首屏只展示关键信号
  - 顶部摘要区必须包含：
    - 当前科目
    - 今日推荐动作
    - 薄弱章节摘要
    - 一个主 CTA（继续训练）
    - 一个次 CTA（切换到真题/模拟）
  - `PracticeSubjectBar` 定位：
    - 一级导航，不是普通筛选器
    - 视觉上必须像“当前训练上下文切换”
    - 切换科目后主栏与教练板同步刷新
  - `PracticeModeGrid` 定位：
    - 只放五种练习方式入口
    - 每张卡要回答：适合什么场景、预计投入、当前是否推荐
    - 第一张卡固定为“今日推荐入口”
  - `ChapterProgressSection` 定位：
    - 承接“章节训练推进”
    - 优先展示掌握度、最近进度、建议动作
    - 在主页面里比真题卷库更靠前，因为它更像日常训练主路径
  - `PastPaperLibrarySection` 定位：
    - 作为“正式演练入口”
    - 优先级低于章节训练，但高于历史信息展示
  - `PracticeCoachPanel` 定位：
    - 不是装饰性分析侧栏，而是“教练建议与风险提示”
    - 主页面只保留 3 类信息：知识结构、考试预测、薄弱点
    - 不堆满零碎图表
  - CTA 层级：
    - 主 CTA：继续最合适的下一步训练
    - 次 CTA：进入另一种高价值训练模式
    - 三级动作：查看详情、切换章节、浏览全部试卷
  - 空态策略：
    - 无数据时不显示空洞分析图
    - 主页面空态仍要提供可执行入口，例如“先从 Smart Drill 开始”
  - 信息密度原则：
    - 主页面允许高密度，但必须有强分区
    - 一屏内不超过一个视觉强焦点，避免主栏和侧栏同时抢注意力

### T-004.4 Smart Drill 方案
- 页面对象：`/dashboard/practice/smart-drill`
- 目标：定义为“个性化精准训练”，不是通用 quiz 页面。
- 需要定义：
  - 启动态信息：推荐原因、预计题量、建议时长、弱点覆盖
  - 训练态 HUD：题号、连续命中、正确率、剩余题量
  - 答题节奏：作答、校验、解释、下一题
  - 结果态：本轮练习成效、下一轮建议
- 冻结结论：
  - 页面定位：今日最优训练入口，强调“为什么现在练这组题”
  - 页面结构：
    - 顶部：训练标题 + 科目 + 返回路径
    - 启动态摘要卡：推荐原因、覆盖章节、题量、预计时长、当前收益
    - 进行态：顶部紧凑 HUD + 单题聚焦答题区
    - 结果态：训练总结卡 + 下一步建议
  - 启动态必须包含：
    - 推荐理由（基于弱点或最近表现）
    - 本轮覆盖章节数
    - 预计题量和预计时长
    - 建议结果（例如“优先修复代数基础”）
  - 训练态 HUD：
    - 当前题号 / 总题数
    - 当前正确率
    - 连续命中
    - 剩余题量
    - 退出入口
  - 答题节奏：
    - 选择答案 -> `Check Answer`
    - 错误/正确反馈立即出现
    - 解析内联展开，不跳离当前节奏
    - 主按钮切换为 `Next`
  - 视觉原则：
    - 不做大面积结果色铺底
    - 题面区域优先可读性，解释区与反馈区次级呈现
    - 更像“精准训练回合”，不是普通问答表单
  - 结果态必须包含：
    - 正确率
    - 命中弱点数量
    - 表现最佳/最差主题
    - 一个主 CTA（继续下一组推荐训练）
    - 一个次 CTA（回到练习中心）

### T-004.5 Error Wiper 方案
- 页面对象：`/dashboard/practice/error-wiper`
- 目标：从赛博游戏皮肤收敛为“错因修复实验室”。
- 需要定义：
  - 进度区：已修复 / 待修复 / 当前 streak
  - 错因表达：错误类型、掌握恢复、修复信号
  - 结束态：本轮修复成果与复盘建议
  - 视觉边界：保留成就感，不使用过强 neon 发光体系
- 冻结结论：
  - 页面定位：错因修复实验室，而不是“打怪清图”
  - 页面结构：
    - 顶部修复进度条
    - 当前错题修复卡
    - 下一个待修复预告
    - 结束复盘卡
  - 顶部区必须包含：
    - 已修复题数
    - 待修复题数
    - 当前 streak
    - 当前修复进度百分比
  - 当前题卡必须包含：
    - 题目正文
    - 掌握恢复层级
    - 错因标签（概念错 / 计算错 / 粗心 / 审题偏差）
    - 提交、继续两个明确动作
  - 反馈策略：
    - 正确时强调“已恢复一层掌握”
    - 错误时强调“仍需复盘”，而不是强烈失败惩罚
    - 红色只用于错误信号，不作为整页主色
  - 空态 / 全清态：
    - 呈现为“修复完成”，不是夸张庆祝页
    - 提供两个出口：回到练习中心 / 开始新训练
  - 结束态必须包含：
    - 本轮修复数量
    - 仍待修复数量
    - 最常见错误类型
    - 建议下一步（回 Smart Drill 或进入章节训练）

### T-004.6 Mock Arena 方案
- 页面对象：`/dashboard/practice/mock-arena` 及 `[examId]`
- 目标：定义为“模拟考试桌面”。
- 需要定义：
  - `MockArenaSetup` 的信息架构
  - 考试规则确认与风险提醒
  - 考试进行中布局：计时、题目区、答题卡、标记复查
  - 交卷确认与结果摘要结构
- 冻结结论：
  - 页面定位：正式演练，不给“训练模式”风格干扰
  - `MockArenaSetup` 结构：
    - 左：考试配置（科目、难度、题量）
    - 右：考试摘要（预计时长、配额、规则、得分说明）
    - 顶部单独展示周配额与限制信息
  - 考前确认必须显示：
    - 本次考试时长
    - 提交后是否可重做
    - 未作答题目处理方式
    - 当前周配额影响
  - 考试页布局：
    - 顶部固定考试状态栏：倒计时、已答数量、交卷按钮
    - 主区：题目卡
    - 右侧：答题导航器
    - 底部：上一题 / 下一题
  - 视觉原则：
    - 最严肃、最克制的一种模式
    - 不使用“推荐”“成就感”强视觉
    - 强化时间和答题秩序感
  - 交卷确认框必须显示：
    - 已答题数
    - 未答题数
    - 标记复查题数
    - 二次确认动作
  - 结果摘要必须包含：
    - 总分、正确题数、错误题数、用时
    - 题号回顾矩阵
    - 错题解析入口
    - 一个主 CTA（继续练习薄弱点）
    - 一个次 CTA（回到 Mock Arena）

### T-004.7 Chapter Progress 方案
- 页面对象：主页面章节区 + `/dashboard/practice/chapter-drill/[chapterId]`
- 目标：把当前名不副实的 `Chapter Map` 改成明确的章节进度板体系。
- 需要定义：
  - 章节节点结构
  - 掌握度、题量、上次练习、推荐动作的展示方式
  - 主页面入口与 drill 页面之间的关系
  - 是否呈现路径感或节点连接感
- 冻结结论：
  - 主页面术语统一为 `Chapter Progress`
  - 主页面区块定位：章节训练推进板，而不是地图可视化
  - 主页面列表卡必须包含：
    - 章节编号
    - 章节名
    - 当前掌握度
    - 热点/薄弱标签
    - 推荐动作（Start / Strengthen / Review）
  - 章节排序原则：
    - 优先推荐当前最有训练价值的章节
    - 不强制纯自然顺序作为主排序
  - `Chapter Drill` 页面关系：
    - 主页面是入口页
    - Drill 页面是单章节专注训练页
  - `ChapterDrillSession` 结构：
    - 顶部专注状态条
    - 主题目区
    - 桌面端保留章节侧栏
    - 解析与提示都在主区内联呈现
  - 视觉原则：
    - 主页面章节区强调“推进”
    - Drill 页面强调“专注”
    - 不使用蜂巢、节点、路径图作为主页面主表达方式

    - 年份
    - 试卷标题/来源
    - 题量
    - 更新状态或完成状态
  - 动作优先级：
    - 首次未做：`Start`
    - 已做未完成：`Continue`
    - 已完成：`Retry`
  - 详情页结构：
    - 顶部试卷信息条
    - 题目练习区
    - 返回卷库路径明确
  - 空态策略：
    - 不说“暂无内容”就结束
    - 要给出可行动路径，如“先从章节训练建立基础”
  - 视觉原则：
    - 更像档案库、资料库
    - 减少娱乐化和模式化装饰
    - 信息字段比图形装饰更重要

### T-004.9 PracticeCoachPanel 方案
- 页面对象：右侧分析栏
- 目标：统一教练板语义，不再是零散的分析组件拼接。
- 需要定义：
  - 固定面板：知识网络、考试预测、薄弱点
  - 模式相关面板：当前推荐动作、最近训练信号
  - 哪些信息在主页面显示，哪些在模式页显示
- 冻结结论：
  - 命名统一为 `PracticeCoachPanel`
  - 主页面固定只保留三块：
    - Knowledge Structure
    - Exam Forecast
    - Weakness Focus
  - 面板顺序：
    - 先结构（你知道什么）
    - 再预测（你可能考到哪里）
    - 再动作（你下一步修哪里）
  - 每块内容上限：
    - 不超过一个主图形
    - 不超过一个说明段
    - 必须有一个可执行动作或跳转
  - 主页面右栏定位：
    - 辅助决策，不抢主栏训练入口
  - 模式页策略：
    - Smart Drill / Error Wiper / Chapter Drill 可展示精简版 coach 信号
    - Mock Arena 考试中不展示教练板，避免干扰正式答题
    - Past Paper 作答中不展示完整教练板，保持试卷纯净
  - 数据可视化边界：
    - 优先摘要与结论
    - 图形只是解释，不是主角
    - 避免为了“可视化”引入噪声

### T-004.10 练习中心共用设计合同冻结
- 目标：把 `T-004.2 ~ T-004.9` 的结论整理成统一设计合同。
- 需要冻结：
  - 标题体系
  - 面板体系
  - CTA 体系
  - 空态、加载态、错误态
  - 状态标签与进度条表达
  - 移动端适配原则
- 冻结结论：
  - 标题体系：
    - 页面标题：训练目标导向，避免营销式口号
    - 区块标题：名词 + 结果导向副标题
    - 指标标题：短、硬、直接
  - 面板体系：
    - 页面主面板：深色实体面板，中大圆角
    - 子面板：更轻一级，弱描边
    - 浮层：仅在确认、提示、二次操作时出现
  - CTA 体系：
    - 主 CTA：实心冷钴蓝
    - 次 CTA：描边或弱填充
    - 危险 CTA：只在提交/删除/放弃时使用危险色
  - 空态体系：
    - 空态必须包含“为什么空”和“下一步能做什么”
    - 不允许只写一句 `No data`
  - 加载态体系：
    - 优先骨架屏，不使用通屏转圈
    - 骨架尽量接近最终版布局
  - 错误态体系：
    - 错误文案明确说明影响范围
    - 必须有重试或返回路径
  - 状态标签：
    - 推荐、薄弱、热点、已完成、锁定 等标签统一样式语义
    - 标签只传达状态，不承担主 CTA 功能
  - 进度表达：
    - 进度条、掌握度、题号进度统一使用横向线性表达
    - 星级仅保留在章节掌握度场景，不扩散到全系统
  - 移动端规则：
    - 先动作，后分析
    - 固定栏数量减少
    - 吸顶只保留一层
  - 一致性要求：
    - 五种模式共享同一套标题、按钮、状态反馈语言
    - 不允许单个模式自行创造新视觉体系

## T-005 详细任务说明

### T-005.1 全局 token 冻结
- 从练习中心视觉规则抽出全局变量：
  - 颜色
  - 圆角
  - 阴影
  - focus ring
  - surface 层级
- 目标文件：`globals.css` 与 Tailwind 语义层。
- 冻结结论：
  - 颜色 token 改为语义优先，不再依赖页面内直接写死 `blue-600 / slate-800 / purple-*`
  - 全局颜色组：
    - `canvas`：应用最外层背景
    - `shell`：页面壳层 / layout 背景
    - `surface-1`：主面板
    - `surface-2`：次级面板 / 内嵌容器
    - `surface-3`：浮层 / 弹层 / 吸顶条
    - `primary`：冷钴蓝
    - `success / warning / danger / muted`
  - 文本层级：
    - `text-primary`：主标题、核心内容
    - `text-secondary`：说明、标签、副标题
    - `text-tertiary`：弱提示、占位
    - `text-inverse`：反色文字
  - 边框层级：
    - `border-subtle`：默认描边
    - `border-strong`：聚焦容器
    - `border-state-*`：状态描边
  - 圆角尺度：
    - 页面主面板：20-24px
    - 普通卡片：16-20px
    - 输入框与按钮：12-14px
    - 小标签：999px 或 10px，按语义二选一
  - 阴影策略：
    - 默认用层级和描边，不依赖重阴影
    - 仅主浮层和重点卡允许中度阴影
    - 不保留大面积发光阴影作为基础样式
  - focus ring：
    - 统一为主色低透明外环
    - 禁止每个组件各自定义不同 ring 色
  - surface 层级规则：
    - `shell` 与 `surface-1` 明度必须可区分
    - `surface-2` 仅用于卡内嵌套，不应和主卡同级
    - 吸顶条、弹窗、下拉统一走 `surface-3`

### T-005.2 基础控件冻结
- 收敛 `button / card / input / textarea` 的默认态、hover、active、disabled。
- 原则：先统一基础控件，再让页面套规则，不在页面里继续各写各的。
- 冻结结论：
  - `Button`：
    - 全局仅保留 `primary / secondary / outline / ghost / destructive / link`
    - `glow` 不作为应用内基础变体，若保留仅限营销页，不可进入 dashboard / practice 主路径
    - 默认按钮从 `rounded-full` 收敛为中等圆角
    - hover 不使用放大和发光作为基础交互
  - `Card`：
    - 默认卡片使用 `surface-1 + subtle border`
    - 不允许基础 `Card` 自带强白底/强黑底假设
    - 视觉强弱通过 variant 或外部 class 控制，不让页面反复覆写
  - `Input / Textarea`：
    - 使用统一的内嵌面板风格：`surface-2`
    - 聚焦态只通过统一 ring + border 强化
    - 默认高度、内边距、占位文字颜色保持一致
    - 不允许社区页等页面直接手写完全不同的输入风格
  - 组件边界：
    - 应用内所有深色页面优先复用基础控件
    - 若页面需要特殊视觉，必须在共用规则内扩展，不可另起一套体系

### T-005.3 公共空态与 CTA 模板冻结
- 抽出 Dashboard / Leaderboard / Community 共用的空态模板。
- 统一：
  - 空态标题
  - 描述文案结构
  - 主 CTA / 次 CTA
  - 图标区与容器样式
- 冻结结论：
  - 空态模板统一结构：
    - 图标或状态符号
    - 标题
    - 一句解释当前为什么为空
    - 一个主 CTA
    - 可选一个次 CTA
  - 空态文案规则：
    - 先说当前状态
    - 再说为什么会这样
    - 最后给动作
    - 禁止只有 `No data`、`Nothing here` 一类低信息密度文案
  - Dashboard 空态：
    - 重点引导用户开始第一条有效学习路径
  - Leaderboard 空态：
    - 重点引导用户先完成一组练习进入榜单
  - Community 空态：
    - 重点引导用户发第一帖或切换 tab，而不是停留在空白页
  - 错误态与空态区分：
    - 错误态要说明加载失败并给重试
    - 空态是数据正常但暂无内容，不给错误色主视觉
  - CTA 层级：
    - 每个空态最多 1 主 + 1 次
    - 不允许在空态区域放 3 个以上同级动作

### T-005.4 壳层与导航规则冻结
- 统一 `BottomTabBar` 与 `dashboard-layout` 的：
  - 路由映射
  - 激活态规则
  - 视觉层级
  - 移动端与桌面端表现一致性
- 冻结结论：
  - 路由映射必须单一来源，不允许 `BottomTabBar` 与 `dashboard-layout` 各自维护不同 map
  - `currentView` 命名需与真实路由含义一致：
    - `questionBank` 后续应收敛到 `practice`
    - 避免桌面和移动端同页不同命名
  - 激活态规则：
    - 统一使用“当前路由前缀命中 + 例外白名单”策略
    - 不能一处按 `startsWith`，另一处按 `===`
  - 视觉层级：
    - 底部导航比内容高一层，但低于对话框
    - 桌面侧边栏与移动底栏应共用同一视觉语言
  - Dashboard 壳层要求：
    - 去除明显假数据展示块作为长期基础元素
    - 侧边栏 CTA、升级卡、成就卡都必须服从全局 token
  - 移动端要求：
    - tab 数量固定，不因页面局部需求动态增减
    - active 状态统一使用主色与轻量指示，不用额外放大或花哨动效
