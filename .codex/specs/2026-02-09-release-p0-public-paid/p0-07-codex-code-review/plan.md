# 技术方案（Plan）

## 概览
- 子任务：P0-07 Codex Code Review 与风险收敛
- 方案摘要：先固定 findings 和优先级，再按风险闭环推进修复与验证，避免后续 P0 在不稳定基线上继续开发。
- 执行原则：先文档、后实现；未获用户确认前禁止进入修复代码。

## 强制门禁（本任务必须满足）
1. 完成 `spec.md`、`plan.md`、`tasks.md`、`acceptance.md` 四件套并通过审阅。
2. Findings 必须包含：严重级别、文件位置、风险说明、修复建议。
3. 每项高优先级风险必须绑定最小验证命令与通过标准。
4. 验证环境固定为本地 + 预发（如涉及 DB 迁移链路）。

## Review / 修复清单
| 类别 | 风险项 | 严重级别 | 处理策略 | 验证命令 |
|---|---|---|---|---|
| DB 发布链路 | 009 启用 RLS 后若缺少 010 策略会导致访问拒绝 | P1 | 迁移绑定发布 + 覆盖检查 | `supabase db push` 后策略核对 SQL |
| 测试回归 | `data-service` 单测 mock 缺失 `prisma.user` | P2 | 对齐 mock 与实现依赖 | `pnpm vitest --run src/actions/practice/__tests__/data-service.test.ts` |
| 门禁失真 | 全量 lint 存量过大导致新增问题难识别 | P2 | 分层治理 + 增量门禁 | `pnpm lint`（分目录） |

## 数据落表点与核对范围
| 相关表 | 关键字段 | 核对目标 |
|---|---|---|
| pg_policies / 业务表策略 | schemaname、tablename、policyname | 启用 RLS 的业务表均有策略覆盖 |
| users / user_permission_overrides | role、expiresAt | 测试中用户权限分支可被正确模拟 |

## 验证步骤（固定流程）
1. 本地：执行定向测试与策略覆盖检查，记录结果。
2. 预发：复测迁移与关键查询路径，确认无锁库风险。
3. 回归：对 Practice 与 P0 主路径执行最小冒烟。

## 风险与回滚
- 触发回滚：策略覆盖不完整、关键测试失败、门禁无法执行。
- 回滚步骤：撤销对应迁移/修复提交，恢复前一稳定版本并复测。
- 观测要求：记录执行人、时间、命令、结果与证据链接。

## 开发启动条件
- 用户确认 findings 与修复优先级后，才允许进入代码实施。
