# 技术方案（Plan）

## 概览
- 目标：以 文档先行 + 门禁驱动 的方式推进 P0 上线。
- 范围：P0-00 到 P0-10（含 Leaderboard、Community、Achievement、UI、支付）。
- 当前约束：未获用户批准前，不进入任何代码开发。

## 全局强制门禁
1. 每个 P0-xx 必须完成四件套并通过文档审阅。
2. 每个 P0-xx 必须补齐两张矩阵：
   - Server Action 验证矩阵
   - 数据表核对矩阵（SQL 前后快照）
3. 验证环境固定：本地 + 预发。
4. 验收证据固定：写入各任务 acceptance.md。

## 公共接口与类型补充要求
每个子任务 plan.md 涉及 Action 或接口时，必须写清：
- 输入参数与校验规则
- 返回结构与错误结构
- 数据落表点（表 + 关键字段）
- 幂等与并发策略
- 审计字段（至少 userId、action、result、timestamp）

## 执行顺序
1. 文档重写：按依赖顺序完成 p0-00 到 p0-10。
2. 文档确认：每个任务单独等待用户确认。
3. 开发实施：仅对已确认任务开工。
4. 本地验证 + 预发复测：每个任务完成后回填矩阵证据。

## 风险与回滚
- 风险：开发先于文档导致返工；验证无证据导致上线不可审计。
- 缓解：门禁强制 + 证据模板统一。
- 回滚：出现阻断问题时，按子任务粒度回滚并复测。
