# 技术方案（Plan）

## 概览
- 方案摘要：建立上线前专项测试任务，先覆盖 referral 与 notification 两条链路，并提供可追踪证据。
- 预期收益：降低上线后支付奖励与通知链路故障风险。

## 实现步骤
1. 建立并维护专项测试项清单（按场景、数据表、证据分类）。
2. 执行 referral 测试并记录 SQL 快照与事件日志。
3. 执行 notification 测试并记录可视化/数据库证据。
4. 汇总结论并回写 acceptance 与 P0 总任务进度。

## 接口与类型变更（Public APIs / Interfaces / Types）
- 路径：无新增对外接口。
- 变更内容：本任务以测试验证为主，不引入接口契约变更。
- 兼容性影响：无。

## 数据流
- 输入：测试账号、支付事件、通知触发事件。
- 处理：执行业务动作并核对 `users/referrals/notifications` 变化。
- 输出：测试结论与证据（SQL、日志、截图）。

## 迁移策略（如有）
- 无。

## 回滚策略
- 触发条件：测试过程中发现会影响上线的阻断问题。
- 回滚步骤：暂停上线 -> 回退相关改动 -> 复测关键场景。

## 监控与观测（如有）
- 指标：支付后 referral 奖励成功率、通知创建成功率、重复事件处理数。
- 告警阈值：任一关键场景出现阻断即不允许上线。
